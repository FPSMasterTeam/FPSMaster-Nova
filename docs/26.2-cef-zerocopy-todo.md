# 待办:26.2 CEF 零拷贝(GPU 加速)渲染

> 状态:**暂缓**。26.2 上 Web UI 走 **CPU 上传路径**已能正常渲染出图;零拷贝(zero-copy)加速路径被 stub。本文记录为什么、以及怎么补。
>
> 相关代码:
> - `src/main/kotlin/top/fpsmaster/web/cef/AcceleratedBrowserTexture.kt`(26.2 为 stub)
> - `src/main/kotlin/top/fpsmaster/web/cef/BrowserOwnedTexture.kt`(26.2 CPU 路径,已实现)
> - `src/main/kotlin/top/fpsmaster/web/cef/ClientBrowser.kt`(draw / `useAccelerated` 分支)
> - `src/main/kotlin/top/fpsmaster/render/shaders/ShaderManager.kt`(bgra shader,26.2 为 stub)
> - 背景见 [多版本文档](multiversion.md) 与记忆 `nova-mc26-unobfuscated-build`

## 零拷贝是什么

mcef-nova 在 CEF 线程把 CEF 的 GPU 共享纹理 import 成一个原生 GL 纹理 id;零拷贝路径**不拷贝像素**,直接把这个已存在的 GL id 包装成 blaze3d 的 `GlTexture` 来绘制。对比 CPU 路径(`BrowserOwnedTexture`):CPU 路径每次 CEF paint 都要把 BGRA 缓冲拷进一张 `GpuFormat.RGBA8_UNORM` 纹理、并在 CPU 端做 B↔R swizzle。零拷贝省掉这次拷贝 + swizzle。

**收益范围**:仅 **Windows/Linux**(CEF GPU 共享纹理 interop,`Util.checkAccelerationSupport` 只放行 N卡/A卡),macOS 恒走 CPU。且当前 `accelerate` 默认 **opt-in 且关闭**(所有版本)。所以主要利好 Win/Linux 上的动画/视频类网页内容;静态 UI 下 CPU 路径开销很小。

## 为什么 26.2 没做(三个障碍)

### 1. 反射的 `GlTexture` 构造器签名变了(直接原因)
`GlTexture` 构造器是 `protected`,只能反射调用。26.2 改了签名:
```
// 1.21.11: GlTexture(int, String, TextureFormat, int,int,int,int, int)                       // 8 参
// 26.2:    GlTexture(int, String, GpuFormat,     int,int,int,int, int, FrameBufferCache)      // 9 参
```
- `TextureFormat` → `com.mojang.blaze3d.GpuFormat`
- **新增末参 `com.mojang.blaze3d.opengl.FrameBufferCache`**

`GlTextureView` 同样多了这个参:
```
// 1.21.11: GlTextureView(GlTexture, int, int)
// 26.2:    GlTextureView(GlTexture, int, int, FrameBufferCache)
```
旧反射按 8 参签名 `getDeclaredConstructor(...)`,26.2 找不到 → `NoSuchMethodException` → `isSupported=false` 回退。这是 stub 的直接原因。

### 2. 无法在 CPU 端 swizzle,需要 shader
CEF 给 BGRA,26.2 没有 BGRA 的 `GpuFormat`。CPU 路径靠上传时 CPU 端交换 B↔R;但零拷贝直接用 mcef 的 GPU 纹理,**碰不到像素**,只能靠 shader 在采样时交换。旧代码用 `pipeline/jcef/bgra_blurred_texture` 这个自定义 shader 做,而它在 26.2:
- `ShaderManager` 被 stub(`RenderPipeline.Builder` 的 `withBlend`/`withVertexShader`/`withSampler`/`withDepthTestFunction`/`withVertexFormat` 等 fluent API 全改名)
- 旧的自定义管线绘制 `guiGraphics.submitGuiElement(TexQuadGuiElementRenderState(pipeline, textureSetup, …))` 整套 submit-node API 已移除(见 [多版本文档](multiversion.md))

而 26.2 CPU 路径用的 `GuiGraphicsExtractor.blit(view, sampler, …)` 走的是**固定** `GUI_TEXTURED` 管线,不带 swizzle。

### 3. 平台/环境
Win/Linux only,且默认关;开发机(macOS)验证不了。

## 怎么补

关键前置发现:`FrameBufferCache` 可从 **公开** API 拿到——`com.mojang.blaze3d.opengl.GlDevice.frameBufferCache()`(public),也有 public 无参 ctor(但优先用 device 上的实例以共享状态)。

### 第一步(简单):修反射,让纹理包装能通
在 `AcceleratedBrowserTexture` 的 26.2 分支:
```kotlin
val device = RenderSystem.getDevice() as com.mojang.blaze3d.opengl.GlDevice
val fbCache = device.frameBufferCache()                    // 公开 API
val ctor = Class.forName("com.mojang.blaze3d.opengl.GlTexture").getDeclaredConstructor(
    Int::class.javaPrimitiveType, String::class.java, GpuFormat::class.java,
    Int::class.javaPrimitiveType, Int::class.javaPrimitiveType,
    Int::class.javaPrimitiveType, Int::class.javaPrimitiveType, Int::class.javaPrimitiveType,
    FrameBufferCache::class.java)                            // 9 参新签名
ctor.isAccessible = true
val tex = ctor.newInstance(texId, "FPSMaster browser accel", GpuFormat.RGBA8_UNORM,
    width, height, 1, 1, GpuTexture.USAGE_TEXTURE_BINDING, fbCache) as GpuTexture
// GlTextureView 同理:getDeclaredConstructor(GlTexture, Int, Int, FrameBufferCache).newInstance(tex, 0, 1, fbCache)
```
> 更干净的替代:用 access widener 开放这两个 `protected` ctor,免反射。注意零拷贝 id 由 mcef 管生命周期——**绝不能 close 这个 GlTexture**(会 glDeleteTextures 掉 mcef 还在用的 id,双重释放),沿用现有"每帧造一次性 wrapper 直接丢弃"的做法。

### 第二步(较难):解决 BGRA,三选一
- **A. 上 bgra shader(还原旧设计)**:把 `ShaderManager` 的 `RenderPipeline.Builder` 移植到 26.2 API,再用**自定义管线**画这张纹理。难点:26.2 `blit(view, sampler)` 固定 `GUI_TEXTURED`;要自定义管线得自己造一个 `net.minecraft.client.renderer.state.gui.BlitRenderState`(或别的 `GuiElementRenderState`)并塞进 `GuiRenderState`——需查 26.2 新的提交方式(`GuiGraphicsExtractor.innerBlit(RenderPipeline, …)` 是 private;可能要 mixin/AW 暴露,或复刻其构造 `BlitRenderState` + `addGuiElement` 的逻辑)。
- **B. 让 mcef 输出 RGBA**:若 mcef-nova 能让 CEF 直接输出 RGBA(而非 BGRA),零拷贝就能直接用固定 `blit`,无需 shader。需改 mcef fork。
- **C.(仅验证用)** 先接受红蓝互换,确认零拷贝能上屏,再补颜色。

### 打开开关
`ClientBrowser` 的 `accelerate` 现为 opt-in;`AcceleratedBrowserTexture.probe()`/`isSupported` 在 26.2 stub 里恒 false,补完后改回真实探测,并确保 `ClientBrowser.render` 的 `>=26` 分支在 `useAccelerated` 时走加速纹理(而非当前恒 CPU 的 `ownedTexture`)。

## 建议顺序
1. 第一步反射修复(低风险),先确认 GL id 能包成 `GpuTextureView`。
2. 第二步选 A(bgra shader + 自定义 `BlitRenderState`)——这是"正确"实现;卡点在 26.2 自定义 GuiElement 的提交路径。
3. 全程在 **Windows/Linux + N/A 卡** 上测(macOS 无此路径)。
